## 1. Скриншоты

### 1.1 Захват экрана через CLI

---

#### TC-CAP-001: CLI-режим захватывает скриншот и печатает путь

- **Описание**: При запуске `rustshot --cli` программа делает скриншот основного монитора и выводит путь к файлу в stdout.
- **Ожидаемый результат**: stdout содержит строку вида `Screenshot saved to: <путь>`, файл существует на диске.
- **Тип**: интеграционный (unit через `run_cli_with_capture` с mock-функцией захвата)

---

#### TC-CAP-002: `--list` выводит список экранов

- **Описание**: Запуск `rustshot --list` возвращает строку `Available screens:` с записями `Screen N: WxH` для каждого монитора.
- **Ожидаемый результат**: Возвращается непустая строка с заголовком `Available screens:`; каждая строка экрана начинается с `Screen ` и содержит символ `x`.
- **Тип**: юнит (`format_screen_list_output` + `list_screens`)

---

#### TC-CAP-003: `--list` с пустым списком экранов

- **Описание**: Если `list_screens()` вернул пустой вектор, `format_screen_list_output` возвращает только заголовок без записей.
- **Ожидаемый результат**: Строка равна `"Available screens:"`.
- **Тип**: юнит

---

#### TC-CAP-004: `--list` не мешает захвату — флаг `list` обрабатывается до вызова capture

- **Описание**: `run_cli_with_capture` при `args.list == true` возвращает список экранов и не вызывает функцию захвата.
- **Ожидаемый результат**: `capture_fn` не вызывается; результат содержит `Available screens:`.
- **Тип**: юнит

---

#### TC-CAP-005: `--output` задаёт явный путь сохранения

- **Описание**: При передаче `--output /tmp/shot.png` файл сохраняется именно по этому пути.
- **Ожидаемый результат**: `capture_fn` получает `Some(PathBuf::from("/tmp/shot.png"))` в качестве `output`.
- **Тип**: юнит (`run_cli_with_capture`)

---

#### TC-CAP-006: Ошибка захвата выводится в stderr и завершает процесс с кодом 1

- **Описание**: Если `capture_fn` возвращает `Err("capture failed")`, `run_cli` выводит `Error: capture failed` в stderr и завершается с кодом выхода 1.
- **Ожидаемый результат**: `run_cli_with_capture` возвращает `Err`; вызывающий код вызывает `process::exit(1)`.
- **Тип**: юнит

---

#### TC-CAP-007: `should_run_cli_mode` активируется флагами `--cli`, `--list` и `--output`

- **Описание**: Функция `should_run_cli_mode` возвращает `true` если хотя бы один из флагов установлен.
- **Ожидаемый результат**:
  - `--cli` → `true`
  - `--list` → `true`
  - `--output foo.png` → `true`
  - (ничего) → `false`
- **Тип**: юнит

### 1.2 Форматы: PNG, JPG, BMP

---

#### TC-FMT-001: `Format::extension()` возвращает правильное расширение

- **Описание**: Каждый вариант перечисления возвращает соответствующую строку расширения файла.
- **Ожидаемый результат**: `Png` → `"png"`, `Jpg` → `"jpg"`, `Bmp` → `"bmp"`.
- **Тип**: юнит (уже реализован: `format_extension_is_correct`)

---

#### TC-FMT-002: `Format::to_image_format()` возвращает правильный `ImageFormat`

- **Описание**: Каждый вариант маппируется на соответствующий формат библиотеки `image`.
- **Ожидаемый результат**: `Png` → `ImageFormat::Png`, `Jpg` → `ImageFormat::Jpeg`, `Bmp` → `ImageFormat::Bmp`.
- **Тип**: юнит (уже реализован: `format_to_image_format_is_correct`)

---

#### TC-FMT-003: Все три `ImageFormat` различны между собой

- **Описание**: Маппинги PNG, JPG и BMP не пересекаются.
- **Ожидаемый результат**: Все три значения `to_image_format()` попарно не равны.
- **Тип**: юнит (уже реализован: `format_to_image_format_distinct`)

---

#### TC-FMT-004: Расширения в нижнем регистре

- **Описание**: Метод `extension()` возвращает строки только из строчных букв.
- **Ожидаемый результат**: `ext == ext.to_lowercase()` для всех трёх вариантов.
- **Тип**: юнит (уже реализован: `format_extension_is_all_lowercase`)

---

#### TC-FMT-005: Формат по умолчанию — PNG

- **Описание**: `Format::default()` должен возвращать `Format::Png`.
- **Ожидаемый результат**: `matches!(Format::default(), Format::Png)` == true.
- **Тип**: юнит (уже реализован: `format_default_is_png`)

---

#### TC-FMT-006: `capture_screenshot_with` передаёт правильный `ImageFormat` в `save_image` для PNG

- **Описание**: При использовании `Format::Png` функция `save_image` получает `ImageFormat::Png`.
- **Ожидаемый результат**: наблюдаемый `image_format == ImageFormat::Png`.
- **Тип**: юнит (уже реализован: `capture_screenshot_with_uses_png_image_format_for_png`)

---

#### TC-FMT-007: `capture_screenshot_with` передаёт правильный `ImageFormat` для JPG и BMP

- **Описание**: Аналогично TC-FMT-006 для форматов JPG и BMP.
- **Ожидаемый результат**: `ImageFormat::Jpeg` для JPG; `ImageFormat::Bmp` для BMP.
- **Тип**: юнит (уже реализованы: `capture_screenshot_with_image_format_for_jpg`, `_for_bmp`)

---

#### TC-FMT-008: `CliFormat` корректно конвертируется в `capture::Format`

- **Описание**: Все три варианта `CliFormat` через `From` преобразуются в соответствующий `capture::Format`.
- **Ожидаемый результат**: `CliFormat::Png` → `Format::Png`, аналогично для Jpg и Bmp.
- **Тип**: юнит

- TC-SESSION-003 — TC-SESSION-004: реальный жизненный цикл сессии — требует Windows.

### Низкий
- TC-RECERR-003, TC-RECERR-004: устойчивость к ошибкам в цикле захвата — проверяется только вручную или тяжёлыми интеграционными тестами с mock-слоем WMF.

---

## 5. Что намеренно не покрыто

- **GUI-тесты** `SelectionApp` (событийный цикл `winit`): проверяются только без surface — создание окна и обработка мыши требуют отображения.
- **Тесты с реальной камерой/WMF** (TC-SESSION-003, TC-RECERR-002): требуют инфраструктуры CI с дисплеем; запускаются вручную.
- **Трей и глобальные хоткеи**: тестируются вручную, так как требуют интеграции с оконной системой Windows.
- **Autorun через реестр**: побочный эффект ОС; не тестируется автоматически.
