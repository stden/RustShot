# 🤖 CLAUDE.md

Инструкция для Claude при работе с RustShot.

## ✅ Самое главное

- Делай маленькие и понятные изменения.
- Не ломай текущее поведение без причины.
- Если что-то меняешь, добавляй тест.
- Не устраивай большую архитектурную перестройку, если задача маленькая.

## 📁 Как устроен проект

Сейчас проект маленький. Основные части такие:

- `src/main.rs` — запуск программы и CLI
- `src/capture.rs` — скриншот и сохранение файла
- `src/selection.rs` — выбор области мышкой
- `src/tray.rs` — трей и меню
- `src/record.rs` — запись экрана
- `src/settings.rs` — сохранение настроек и работа с файлом настроек

## ⚡ Какие команды запускать

```bash
cargo check          # Проверить сборку
cargo test           # Запустить тесты
cargo fmt            # Отформатировать код
cargo clippy         # Проверить линтером
cargo bench          # Запустить бенчмарки
cargo build --release # Сборка релиза
```

## ✍️ Конвенция коммитов

- `[+]` — добавления (новые фичи, новые тесты)
- `[-]` — удаления (удаленные фичи, удаленный код)
- `[!]` — рефакторинг, исправления, улучшения

## 📐 Как лучше решать задачи

Рабочий порядок:

1. ✏️ Сначала написать тест.
2. ❌ Посмотреть, что он падает.
3. ✅ Исправить код минимально.
4. ✅ Убедиться, что тест стал зеленым.
5. 🧪 Потом запустить все тесты.

## 🧪 Какие тесты здесь полезнее всего

- Тесты на разбор аргументов CLI
- Тесты на выбор пути и формата файла
- Тесты на ошибки и их текст
- Тесты на маленькие helper-функции

Не стоит без крайней необходимости усложнять проект тяжелыми GUI-тестами.

## ⚠️ Ошибки

- В этом проекте часто используется `Result<_, String>`.
- Сообщения об ошибках должны быть понятными.
- Не прячь ошибки молча, если это не специальное поведение.

## 🌍 Особенности платформ

- 🐧 Linux требует X11-библиотеки.
- 🎬 Запись экрана работает только на Windows.
- 🪟 На Windows есть tray и hotkey, их легко случайно сломать.
- 🧪 Код выбора области и работы с окнами лучше тестировать через маленькие куски логики, а не только вручную.

## 📚 Методология Codev

Проект использует методологию контекстно-ориентированной разработки Codev.

### 🔄 Активный протокол
- Протокол: SPIR
- Расположение: codev/protocols/spir/protocol.md

### 📂 Структура каталогов
- Спецификации: codev/specs/
- Планы: codev/plans/
- Ревью: codev/reviews/

Подробности протокола: codev/protocols/spir/protocol.md

### 📖 Где живёт документация
- **Архитектура и обоснование решений живут в коде**, в rustdoc-комментариях
  к модулям и функциям — начинать с `src/lib.rs`. Отдельный arch-документ не создавать.
- Поведение специфицировано исполняемо: Gherkin-сценарии в `tests/features/`,
  запускаются через `tests/bdd.rs` (`cargo test --test bdd`).
- Общие (не относящиеся к RustShot) практики Rust/тестирования лежат в центральном
  репозитории `iopm` в каталоге `docs/`, а не здесь.
- Карта документации: `docs/README.md`.
